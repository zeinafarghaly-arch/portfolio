My AI Stack

Not a list of logos — the actual layers I use, and the specific reason I reached for each one over the alternative, drawn from real projects on this site.

Data Layer

DuckDB

DuckDBParquetHugging Face-hosted warehouse

For the FlyRank internship I was querying a 9.8M-row warehouse. Loading that into pandas would mean pulling the whole table into memory before I could filter anything. DuckDB runs SQL directly against the columnar files, so I could verify the data contract — row grain, GA4 availability, decision-moment cutoffs — with actual queries against the full dataset, not a sample. Pandas came in only after DuckDB had already cut the data down to something feature-sized.

Classical ML

scikit-learn

Logistic RegressionKNNSVMGroupShuffleSplit

I chose Logistic Regression as the FlyRank scoring model specifically because it outputs a calibrated probability I can rank pages by, and its coefficients are directly readable — I could point to content_age_days and days_since_last_update as the two features actually driving the score, which matters when the output goes to a human editor who'll ask "why this page." I used GroupShuffleSplit by client_id rather than a random row split, because the real deployment question is whether the model generalizes to a client it's never seen — a random split would let the same client leak into both train and test and quietly overstate performance.

Deep Learning

TensorFlow / Keras

Dense networksEarlyStoppingModelCheckpoint

For MNIST and Fashion-MNIST I used Keras's callback system — EarlyStopping monitoring validation loss, ModelCheckpoint saving the best epoch — instead of just training for a fixed number of epochs and taking whatever came out last. On Fashion-MNIST that decision mattered: training accuracy kept climbing past epoch 10 while validation accuracy plateaued, and the callbacks caught the best-generalizing checkpoint rather than the most-overfit one.

Metric Design

Precision@500, not plain accuracy

Precision@kAUC (leakage check)

Accuracy doesn't match how this model is actually used: an editor isn't reviewing every page, they're reviewing a fixed batch. So the metric I committed to before training was Precision@500 — of the top 500 ranked pages, how many are truly declining. I used plain AUC separately, but only as a leakage diagnostic (an honest AUC of 0.598 vs. a leaky 1.000), not as the metric the model was optimized or judged against.

Systems / Languages

Java, Python, SQL

Java + JavaFXSQLitePythonSQL

Language choice tracked the problem, not habit. The hospital management system needed strict role-based state and a desktop UI with real concurrency (background dashboard threads, session timeouts) — Java's type system and thread model fit that better than a scripting language would have. Everything data- and model-facing (FlyRank, MNIST, Fashion-MNIST) is Python, because that's where the ML ecosystem actually lives.

Security & Infra

Cloud Security fundamentals

IAMZero TrustCSPMTerraformChronicle SIEM

From the Google Cloud Cybersecurity Professional Certificate: least-privilege IAM design, Zero Trust network assumptions, and Terraform for reproducible infrastructure — the same "don't trust it until you've verified it" instinct that drove the FlyRank data contract work. Chronicle SIEM and incident response are the monitoring side of that: knowing what to watch once something is deployed, not just how to deploy it safely.

What's next in this stack: everything above is the data + modeling + security foundation. The layer I haven't built yet — LLM API orchestration and tool-calling for a working agent — is the next piece of this capstone.
